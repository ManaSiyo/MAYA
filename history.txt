AUGUST 11 TO 13, 2026

Where we are: MAYA is at v13.3. Saving is trustworthy, the app is fast, the
Systems Map tells the truth, dissection costs credits once instead of every
time, Stripe is live, and there is a community wall.

AUGUST 14, 2026, AFTERNOON

Codex completed the second-eye release, v13.15 through v13.18. The practical
change is simple: project deletion is one cloud act and picture cleanup keeps
retrying instead of becoming a ghost; the Systems Map can no longer confuse
"configured" with "working" or let an old refresh win. The Community wall now
uses the Inspiration-card language, without white glow columns, and Favorites
breathes through a smaller fixed halo rather than a resizing shadow.

The thing that started it: a client's project was saved and then was not
there. The cause was found. Naming a project from the Save box wrote to the
browser's own storage only, while the screen said "Saved". Everything about
the save system was rebuilt on top of that: one save path, cloud only,
"New" genuinely means a new project, and a project is never left without
first confirming it was written.

What else got fixed, in Fromsa's words rather than mine: twenty four copies
of the same card, the same fabric appearing over and over, a heart that
never worked, an X button that did nothing on stacked cards, the screen
refreshing itself every five seconds, dragging that lagged behind the
cursor, being asked to sign in while already signed in, and submissions
that would not appear on the Systems Map.

New in these three days: the Systems Map redesign (one line doors, lights in
the top bar, submissions running the full width, collapsible prompting
engine, a Recent changes list with a green dot when it has not been read),
Operating Room renamed Operations Room everywhere, a deliberate Begin
Dissection button whose result is saved forever, a third admin account, a
Stripe tip button, and the community wall.

The community wall: swipe up from the moodboard instead of down. Everyone's
hearted visions drift past sideways, forever, with no seam. Favorites are
still one swipe below. Hearting a vision now publishes it, which is worth
deciding on deliberately at some point.

Also new: tests/smoke.mjs, the first automated test this project has ever
had. It boots the real server and checks every route. It exists because a
single line written in the wrong order in the server would have made every
AI call hang forever, and nothing but booting it would have found that.

AUGUST 5, 2026, EVENING

Where we are: the whole pipeline works end to end for the first time. A
client submits in MAYA, the submission shows up as a garment bubble on the
Systems Map, clicking it opens the Brief in a new tab with the biography,
vision, measurements and fabric sourcing filled in, the garment gets
dissected into pieces automatically, and the pieces land in the Operating
Room below where Start runs the pattern pipeline on them.

What happened today, in order: audited the whole project fresh, reorganized
the folder (three HTMLs at the root, aesthetics for everything visual, docs
for everything else), fixed all the broken backgrounds and icons, redesigned
the Systems Map to match the MAYA look, renamed everything to Brief and
Operating Room, removed all dashes, fixed the dead Google Drive key so
submissions work again, migrated to this MAYA-new folder under git, and set
up automatic server deploys.

How publishing works now, remember this part:
  ONE ACTION: press "Push origin" in GitHub Desktop. Google then deploys
  BOTH the website and the server by itself, takes about 4 minutes.
  "Deploy MAYA.command" in docs still works as a backup for the website
  only, but you should never need it.

What each root file is:
  index.html    the live MAYA app clients use
  status.html   the Systems Map
  backend.html  the Brief plus Operating Room, the atelier's workroom
  operations.html  the standalone Operating Room (the beta for experiments),
                reachable from the Operating Room Beta door on the Systems Map
  cloudbuild.yaml  the ONE technical file that must stay at the top: Google
                reads it on every GitHub push and deploys the website AND the
                server, moving it breaks the automatic deploys
  aesthetics/   everything visual: ui, fabrics, headshots, the Operating
                Room engine the backend embeds
  docs/         everything else: firebase.json (the deploy borrows it for a
                minute then puts it back), Deploy MAYA.command, the server
                source, pattern R&D (operating-room folder), Vision.pdf,
                Strategy-A.md, and _to_delete which is the trash can, empty
                it any time
