## Implemented locally

1. Reception opens with Fromsa's exact greeting: “Hi this is Maya from Mana Siyo.
   How may I direct your call? Tell me what you're interested in and I'll connect
   you.” Short customer intake, no prolonged design interview before connecting.
   Unsolicited sales do not get transferred; unclear intent gets a question or
   callback option. This is model-guided screening, not guaranteed spam detection.
2. A saved customer inquiry plus caller agreement enables transfer to the fixed
   owner number. The owner hears the name/request and presses 1 to accept.
   Decline, timeout or no answer gets a saved-callback message. Arbitrary transfer
   destinations are impossible through this tool. Provider calls are implemented
   using signed Twilio callbacks and the documented Number screening flow:
   https://www.twilio.com/docs/voice/twiml/number .
3. Outbound briefings persist before dialing and survive an answer/stream handled
   by a different Cloud Run instance. Stream signatures bind caller and briefing
   context, not only call ID. Initial audio buffers while the AI socket opens.
   Incoming blocked contacts are rejected. Owner calls join Messages history.
4. SMS callbacks that arrive before message storage are retained and applied.
   Terminal delivery failures cannot be hidden by late “sent” callbacks.
   Admin shows carrier error codes and has Check delivery for the latest five
   outgoing texts. Arbitrary first messages no longer falsely become consent
   requests. A history-save failure after carrier acceptance warns not to resend.
   Deleted blocked contacts remain accessible for unblocking.
5. Lead rows show name + tier pill without price, then Call/Text/Invoice icons.
   Telephone handset replaces smartphone glyph; Call confirms Maya is placing it.
   Phone stays in Contact. Notes get remaining width. Forms indicator, Reload,
   plus Add lead control and hidden scrollbars. Tier edits now write `tier`.
   Contact names use bound DOM events rather than interpolated JavaScript.
6. Systems/Messages/Logs drawer tabs. Logs shows the original feedback, author,
   source, date and Open/Shipped status. Admin and phone prompts treat direct
   feedback as the primary request queue and distinguish logging from fixing.
7. Feedback writes persist source and text together, retry generation conflicts,
   refuse to overwrite on failed/corrupt reads, and retain older requests rather
   than dropping everything beyond 500. Completion also uses generation checks.
8. Playground: equal Randomize/Replace/Save buttons, explicit awaited cloud save,
   visible save failures, click Client or pencil to rename, and current-face
   preview in the avatar list. Account/context checks surround avatar writes.
9. Playground: saved-pin pagination, deduplication, retry and end-of-list state;
   All Pinterest/My saves selector. Search responses reject stale account or
   search context. Global search still requires provider access/configuration.

Frontend changes are staged only in `playground/index.html`. The production
`frontend/index.html` is unchanged, per the repository's promotion rule.
