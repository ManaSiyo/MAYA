# Aesthetic Control — MAYA design standard

This is the **sole active design specification** for the client app, Admin,
Outbound, Brief, Operations and supporting pages. The interactive
[Aesthetic Control](/aesthetics/aesthetic-control.html) is the visual anchor.
Admin → Systems → Aesthetic Control opens it. The owner can edit the preview
and press **Save** at the bottom. On the live site Save requires an Admin sign-in
and stores only validated presentation settings; all pages load those settings.
On localhost Save affects local pages on that browser origin. No change here
alters data, authentication, sending or account/project boundaries.

## Shared hierarchy

H1–H4 strictly descend in size. Paragraph/interface roles never increase down
the list. The role counter in Typography Controls counts authored source locations
and templates once each, not live elements or records. The role subtotals equal
the category total. The audit is regenerated by
`python3 tests/typography-role-usage.py`.

| Role | Font | Size | Weight | Color | Examples |
|---|---|---:|---:|---|---|
| H1 | Cormorant Garamond | 24px | 300 | white | Brand, dialog and page headline |
| H2 | Cormorant Garamond | 20px | 400 | white | Drawer title, including Systems |
| H3 | Jost | 16px | 400 | white | Section and supporting headline |
| H4 | Jost | 14px | 400 | white | Dashboard number |
| P1 | Jost | 12px | 300 | gray | Paragraph, table, log and model text |
| P2 | Jost | 12px | 400 | white | Label and count |
| P3 | Jost | 10px | 300 | white | Pill and small field label |
| P4 | Jost | 10px | 400 | gray | Caption |

White means RGB 255/255/255. Gray is RGB 170/181/196. No weight exceeds 400.
Sizes use even pixels. Jost 350 remains a comparison option, not a new role.
Role assignments are functional; equivalent settings share a category. Technical
identifiers share P1 settings and retain their monospace font. Old saved P4/P5
settings migrate to P3/P4 on read; the retired standalone technical role is
merged into P1. The API accepts older designs for already-open editors.

## Glass and controls

The current Tap to listen pill is the default glass material: dark fill 18%,
white rim 22%, highlight 28%, blur 22px, saturation 180%, Jost 10px/300,
14px horizontal and 6px vertical padding. The preview also offers proposed
liquid and clear alternatives. Selecting one previews it; Save applies the
selected validated values to the shared glass tokens. Information panels have
separate fill/rim/blur/saturation controls. A surface can be quiet, standard or
overlay intensity. Status colors retain their meaning.

A Pill is a content-width capsule. IconButton is circular and matches the
adjacent pill height. GlassSurface is a rounded information panel. Drawer is the
hamburger panel with an overlay backing. FilterPopover stays readable above
tables. Metric uses compact label/count type. Buttons keep visible keyboard
focus, disabled and loading states. Table cells retain existing alignment until an explicit role alignment is saved; overflow
and long content must remain accessible at 320–1920px widths.

## Owner review controls

Typography has one Edit dropdown beside each H1–H4/P1–P4 heading and one
size/weight/color summary per category. Sample rows show role, preview and
location; they have 6px vertical padding. Usage evidence and font/status
references stay collapsed. The review page starts centered. Each role has a
Centered/Left toggle with an accessible pressed state; Save applies explicit
role alignment to shared text selectors. Existing saved designs without
alignment preserve other pages until the owner saves.

Settings panel controls independently set the editor rectangle fill, border,
corners and padding. These affect only the Aesthetic Control editor, separate
from shared information-panel glass. The populated table preview uses P1 cells,
P2 headers, P3 pills and P4 captions and responds to edits.

## Frontend

`frontend/index.html` is the client-facing MAYA experience. Preserve the
cosmic background and imagery, circular unbordered logo, client workflows and
voice behavior. The shared typography and glass controls apply without
changing page data or layout semantics.

## Backend

Admin, Outbound, Brief, Operations, Privacy, Terms and Verify use the same
roles and material. Dense tables and menus stay legible. Keep account and
project data sealed, and maintain existing integration/auth behavior. Page
layout and content can differ; typography and shared controls do not.

## Implementation and verification

The preview lives in `aesthetics/aesthetic-control.html` with support files in `aesthetics/aesthetic-control/`; shared components and tokens in
`aesthetics/ui/components/`; global application in
`aesthetics/ui/typography-controls.js`. The Admin-authenticated save and public
read endpoints are in `docs/server/server.js`; `docs/server/design-config.mjs`
validates the settings. Served pages load runtime v2; Hosting revalidates this
script instead of caching role mappings for a week. Old aesthetic PDFs were removed;
archived source inventories are evidence only and never override this file or
the saved controls. No page should introduce a competing design specification.
